# Packet Memory：训练前准备与交接清单

本文记录本地准备与老师端 GPU 训练的分工，以及当前代码检查得到的缺口。它不是已完成训练的报告，也不将下列建议自动升级为默认实现。

本地负责把研究问题、输入输出、数据、奖励、评测和运行入口做成可审查、可复现的交付物。老师端执行 GPU 预检、真实采样与优化、保存 checkpoint；双方根据日志继续修正问题。训练是否有效以及目标 GPU 上的兼容性，必须经过实际运行才能确认。

## 2. 建议分六个主题交付

| 主题 | 本地要完成的产物 | 交接前怎样验收 |
|---|---|---|
| A. 训练任务与最小协议 | 明确 Memory 可见来源、输出形式、与 Bank / Answer 的关系；冻结一个版本 | 一个真实状态能完整展示输入、模型输出、程序组装后的 packet、Answer 实际可见内容 |
| B. 数据与监督 | 数据导出器、少量经核对的参考样本、来源记录、训练/开发/测试划分 | 输入不含隐藏目标或未来轨迹；参考结论可追溯；同任务及共享历史不跨集合泄漏 |
| C. 评价与奖励 | 独立记录格式、来源、内容、任务结果、成本；实现拟用于训练的评分入口 | 正确、错误、遗漏、冗余和全部报未知的样例能暴露评分缺陷；同输入不同 packet 的分数区别有解释 |
| D. 采样与执行对接 | 接通模型输出、编译、固定 Answer、环境结果与训练记录；失败明确返回 | 录制输出能完成离线重放；截断、非法引用、API 错误不冒充有效采样或成功结果 |
| E. 对照评测 | 同一 Answer 与相同环境预算下的无 Memory、普通检索、未训练 Qwen packet；人工参考仅作诊断 | 比较用相同状态和可见证据；额外收集信息的参考条件单独标记；局部动作正确与完整任务成功分别统计 |
| F. 服务器交付 | 配置模板、依赖与模型版本说明、启动/恢复/评估脚本、日志字段、少步 smoke 步骤 | 本地可检查配置并跑通不更新参数的路径；目标 GPU 的真实 smoke 留给老师执行 |

每个主题独立说明改动目的、文件、验证结果和限制，便于 review。这里的清单尚未代表对应产物均已完成。

## 3. 已确认的第一阶段研究范围

先固定 Answer 为已选定的 V4 Pro，并记录准确 provider/model ID、prompt、工具协议、解码和预算；首阶段只训练 Memory 的 packet 组织能力。候选来源与调用机会固定，以便解释收益来源。暂不把 Bank 写入策略、动态调用时机和 packet 构造一起联合训练；这些仍可作为后续扩展。

经讨论确认：使用固定、通用的 needs / evidence / unresolved 结构，由模型根据当前任务组织具体内容；允许有依据的简短比较、条件关联和冲突识别，不要求 Memory 完成整个任务，也不强制每个 packet 都包含推断。执行动作仍由 Answer 决定。训练的是同一个 Memory 模型的组织能力，不另加第三个决策模型。

具体的草稿编码和训练 prompt 仍需通过样本说明确定；不能因为最近一次实验使用某个接口，就默认它是最终训练协议。[第一条设计样例与职责边界](training/PACKET_ORGANIZATION_V0_CN.md)复用现有编号选择和前提引用编译器，用来把上述约定具体化，不改变默认运行入口。

第一份交付应展示一条完整样本：

```text
当前任务 + 当前允许访问的 Memory / 观察
  -> 候选来源及其编号
  -> 小模型实际生成的草稿
  -> 程序编译后的 packet
  -> 固定 Answer 的输入与响应
  -> 独立评价记录
```

模型生成的草稿与程序回填的文本分开保存。若训练的是编号选择草稿，SFT target 和 GRPO 的策略概率应对应模型实际生成的内容；原文回填、程序修复和 Answer 输出不能被当成同一次 Memory 采样的 token。

## 4. 训练前能确定与必须实测的部分

- SFT 参考样本需核对语义。旧失败输出可用作诊断输入或反例，不把它们直接当作正向目标；由强模型生成也不等于正确。
- 现有反复使用的 Shopping / Travel / Physics 状态属于开发集。示例引导只能摸底，不能充当独立泛化结果，也不必成为允许准备训练的前置成功门槛。
- 结构合法和引用存在只承担基础检查。内容支持需要独立核对；若引入 LLM judge，先用人工判断校准，记录分歧，不能将其评分当作天然真值。
- GRPO 前须检验同状态真实采样候选是否存在有意义的奖励差异。不能靠增加格式分权重制造看似可训练的信号；评分器使用的隐藏评估信息不得进入模型输入。
- 下游任务结果作为候选奖励需要考虑 API 成本、噪声及长程归因。单步动作改善不等于任务成功；不能用结构得分替代尚未实现的下游奖励。
- 本地先确定数据格式、训练目标、长度统计和预算口径。batch size、精度、LoRA/全参选择及并行参数需结合老师 GPU；配置可先准备模板，不宣称已测显存可用。
- MLX 8bit 模型是当前本地推理产物。服务器训练需明确对应的可训练权重、tokenizer、chat template 与训练后回测路径，不能假设直接把本地量化目录交给旧 launcher 即可训练。
