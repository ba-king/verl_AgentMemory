# Packet 组织：已同意的任务边界与第一条样例

## 1. 已同意的能力边界

给定当前任务、当前允许访问的记忆与观察，由同一个 Memory 模型组织一份服务下一步决策的 packet。第一阶段固定候选来源的获取方式和调用机会，集中训练组织能力；Answer 固定为已选 V4 Pro，并负责选择和执行环境动作。

Packet 采用通用的 needs / evidence / unresolved 结构，具体内容随任务变化。允许有依据的简短比较、条件关联和冲突识别，不要求完整解题，不要求每次都产生推断。不同时联合训练 Bank 写入、更新策略与调用时机。

这些是本轮同意的设计边界。下面的字段编码复用现有实验接口，是可执行的样例载体；尚未将该接口提升为正式 Memory action 或冻结最终训练 prompt，也未增加属性。

## 2. 样例的来源和用途

会议 M-27 是本次人工编写的虚构场景，不来自 MemoryArena。所有房间、时间和人数仅用于说明协议。参考草稿由助手编写，不是 Qwen 的输出，不是外部模型教师轨迹，不是唯一正确答案，也没有产生 Answer 成功率或训练效果。

- [完整输入来源](meeting_m27/sources.json)：当前任务、旧记忆、最新通知、会议室目录和另一场会议的无关记忆。
- [参考草稿](meeting_m27/reference_draft.json)：展示一种有依据的组织方法。
- [编译后的 packet](meeting_m27/reference_packet.json)：程序从原文取回证据并填入来源。
- [本地机械检查记录](meeting_m27/compile_check.json)：记录结构、原文复制和前提引用检查，语义不由它认证。

这条样例可供人工 review。未将其加入任何模型请求或训练数据集；若将来用于示范或训练，同场景及其改写须划入开发/训练侧，不能再作为独立测试任务。

## 3. 从输入到输出

| 输入记录 | 模型需要理解的关系 |
|---|---|
| S001：M-27 必须按最新人数安排，且满足指定时段 | 需求的来源；时段可用与容量是两个条件 |
| S002：旧计划按 8 人准备，优先查看 A 室 | 历史计划及旧人数，不是预订回执 |
| S003：同一会议人数更新为 12，日期时段不变 | 更新适用于同一对象，不能继续沿用 8 人 |
| S004：A 容量 10、B 容量 16，未提供时段可用性 | 支持容量比较，不支持可用性或预订成功 |
| S005：另一场会议 M-26 有投影需求 | 作用域不同，不应变成 M-27 的当前必选条件 |

来源按现有通用分片程序形成 F0001–F0005，编号仅定位原文，不表示正确答案或重要程度。最终数据导出也应由确定规则生成编号，不能用监督答案决定编号或排序。

参考草稿选择前四段原文，关联两个需求。它另外表达两条简短判断：旧人数已经更新；A 的容量不足、B 的容量满足。仍保留 B 时段可用性未知，没有宣称 B 已经可以预订。

保留旧记忆是为了展示冲突处理；不是规定所有 packet 都必须重复旧计划。只保留最新通知和必要证据、并正确表达当前条件，也可能是有效且更短的组织方式。评价不能用逐字匹配参考草稿或固定 evidence ID 集合代替内容判断。

## 4. 模型与程序分别负责什么

| 步骤 | 责任方 | 本例的产物 |
|---|---|---|
| 形成当前允许访问的来源集合与分片目录 | 固定候选器 / adapter / 通用分片程序 | sources 与 F0001–F0005；不替模型判断哪个房间更好 |
| 提取需求、选择证据、写出必要判断和未知 | Memory 模型；本例用人工参考替代 | reference_draft.json |
| 复制选中原文、生成来源、检查引用 | 现有确定性编译器 | reference_packet.json；不验证“推断一定成立” |
| 根据当前 packet 与环境选择动作 | 固定 Answer | 本例未调用、无响应记录 |
| 审核内容并记录任务结果 | 独立评价侧 | 下表是人工参考依据，尚未实现语义自动评分 |

本例使用 build_excerpt_catalog(max_chars=1200) 与 compile_premise_selection。草稿中的 excerpt_id 由程序展开；derived 的 premise_ids 指向已选原文，程序合并其 source_refs。对最终 packet，needs / evidence / unresolved 保持现有结构。

如果这一编码被选为训练输出，SFT 的监督目标应是模型需要生成的草稿，GRPO 的策略概率对应实际采样 token。程序回填的原文不算模型生成；程序补字或纠错也必须另外记录，不能伪装为原始输出。

## 5. 这条样例怎样评价

| 维度 | 本例的人工核对依据 | 应识别的错误 |
|---|---|---|
| 当前需求 | 12 人、明确日期时段和时区、容量与可用性分别保留 | 沿用 8 人；引入另一会议的投影要求；漏掉时段 |
| 证据与对象 | A 对应 10、B 对应 16；更新属于 M-27 | 把价格/容量/条件绑定给另一个对象；把旧计划当执行成功 |
| 有依据的组织 | 10 < 12，16 >= 12；更新规则与旧新记录支持条件变化 | 因旧计划优先 A 就认为 A 合适；没有依据地要求 B 已预订 |
| 未知的边界 | B 容量已知，时段可用性未知 | 否认已知容量；将未知当作不可用或可用；一概报所有信息未知 |
| 冗余与长度 | 同段原文可关联多个需求，不需重复复制 | 为每个 need 复制同一段；以大量输出代替选择 |
| 下游效果 | 需要实际 Answer/环境执行才能记录 | 根据格式通过或人工草稿直接宣称任务完成 |

这些维度先分开记录，不在本轮随意设定奖励权重。没有 derived 的 packet 也可有用；包含 derived 时必须有支持，不能靠数量获得奖励。参考中保留了原任务来明确前提，因此不是最短 packet 的示范。

面向 Answer 的语义内容就是编译后 packet。正式的注入位置、消息角色、既有历史保留及工具协议必须在运行对接时固定，本例不伪造一个已执行的 Answer 请求。可用性尚缺只表示仍需获取证据；不把某一个具体查询动作设为唯一正确动作。

## 6. 这一步完成后继续什么

[Task61 P2 的第一条真实开发样本](shopping61_p2/REVIEW_CN.md)已经整理，包含严格截至决策前的来源、人工参考、编译产物和逐项评价依据。它排除了独立补查页面；实际 retrieved_memories 为空，因此当前只说明如何组织真实浏览前缀，未验证 Bank 检索或 Qwen 能力。

接下来将这些评价维度应用到其他领域的真实开发状态，先校准内容评价，再确定训练数据导出、采样和奖励接口。人工样例通过机械检查只证明接口可处理它，不证明 Qwen 已有该能力，也不证明 SFT / GRPO 将有效。
