# 第一条真实开发样本：Task61 P2，当时已见证据

这条样本演示：已经能确认一部分条件，但还没有足够证据选出最优候选时，Memory 怎样组织信息。参考草稿由助手根据已见前缀编写并逐项核对，供用户 review；不是 Qwen 生成、唯一标准答案或新的实验结果。

## 1. 状态与信息边界

原始状态来自 `v4pro_tasks61_113_full_packet_20260909_r1` 的 Task61 `reference_packet` 分支。选中该分支第 8 次 Answer 请求，即 Product 2 的第 3 次决策之前：本商品已经搜索 iLive 并点击 B00X3KFXJM，返回详情页，但本次决策尚未执行。

保存的 seed 与原始请求逐字核对一致。提供给本样本的是 M001–M016 共 16 条非 system 消息，加上描述当前任务/历史截止位置的 C001 元信息。M012 是当前任务；M016 是最新页面。正文不清洗、不反转义、不按答案筛选。通用分片产生 27 个候选片段，编号按来源顺序生成。

这里有两个必须保留的限制：

- 原始请求中的 retrieved_memories 为空；本例主要利用先前浏览和购买回执，不能算作 Memory Bank 检索成功的证据。
- 这是把真实 Answer 可见的有限历史投影给离线 Memory 构造器；原运行并不存在这次 Qwen Memory 调用。它没有证明正式运行器已经允许 Memory 读取这些内容，更没有定义所有未来步骤都能读全部历史。

不向构造器提供：原始 Answer system 指令、原请求最后附加的规则 packet、该请求的响应、后续轨迹、独立补查的 Q001–Q013 页面、目录全库、隐藏目标、奖励和后续商品输入。任务正文里的 `(ground truth)` 是公开措辞，购买回执中的 Required Targets 是公开计数，二者不是隐藏目标标签。

该状态已经用于多次诊断，作者也知道此前研究结果。因此它明确属于开发样本，不是盲标样本或独立测试任务。同一 Task61 和共享历史的其他状态在划分数据时应一起处理。此前使用补查页面的 Qwen 输出与本例输入不同，不作为本例的配对模型结果。

## 2. 先用简洁的话看参考 packet

**当前需求**：按照题目兼容规则，比较列出的音响候选并选择兼容者中评分最高的；全部商品合计不超过 $420，按顺序购买。

**已有证据**：P1 回执记录买了 B095XMWZB2，花费 $149.99；前序点击和详情标题能将它对应到明确写着 LED 的 Norcent。最近点击的 B00X3KFXJM 对应 iLive ITB105B，详情明确写 Compact、$100、评分 3.6。

**能作的简短判断**：若实际记录的 LED 是当前兼容规则适用的前序对象，iLive 符合其中 Compact 的正向配对条件。预算现余 $270.01；若按显示价格购买 iLive，累计 $249.99，余 $170.01。这些是局部条件判断，不是完整任务成功。

**仍然缺的信息**：其他列出候选的详情评分与完整适用性、后续商品所需费用，以及实际购买对象与题目所称前序 ground truth 的对应关系。不能因此否认已确认的 LED、Compact、评分或预算算术。

这里不会写“VIZIO 比 iLive 更好”。即使我们在另一个补查实验中见过相应信息，它也不属于本样本的可见前缀。也不会要求 agent 去查询隐藏答案；题目的 ground truth 限定只用于保留判断范围，不作为一个必须取得的隐藏标签或停止一切行动的理由。

“未提供某信息”要检查整个允许访问的前缀，不能仅因为它没有被某个 packet 选中就认定原始输入也没有。特别是 LED 已在 M009 明确出现；选漏该段后再写 LED 未知属于组织失败。

可接受不同措辞、其他充分来源组合和更短的 packet。不是必须生成相同 ID、相同七段或三条推断才能得分。没有 derived 时，可评价它是否仍清楚提供关键事实；写了 derived 时必须有充分支持。算错/编造与没有主动做有用计算应分别记录为错误和效用不足，不能混为同一种处罚。

## 5. 用几种错误说法校准判断

以下是人工构造的错误表达，未作为模型轨迹或训练正例保存：

| 错误表达 | 应归类为什么 |
|---|---|
| “没有证据确认此前电视是 LED。” | 与已有明确证据矛盾；M009 有 LED，且可通过点击和回执关联对象 |
| “当前音响评分是 4.1。” | 对象归属错误；4.1 来自 Norcent 电视详情，iLive 为 3.6 |
| “iLive 是所有兼容选项里评分最高的。” | 比较前提不足；不能把已看见的一项当成完整比较 |
| “我们已经看到 VIZIO B099BJV68H 的评分是 4.4。” | 使用输入范围之外的信息；本前缀没有该 ID 或评分。这不等于声称该事实在外部世界为假 |
| “买 iLive 后整套商品肯定不会超预算。” | 从局部预算推到整体可行性；后续费用未建立 |
| “P1 显示 completed，所以它一定就是 ground truth 商品。” | 将公开执行完成当成隐藏目标匹配 |

评价有两个不同问题：packet 内容是否忠于证据；它是否实际帮助 Answer。前者可先人工核对，后者必须用同状态、同模型的实际决策或续跑检验。本例没有后者的测量值，不能把本表直接换算成成功率。

## 6. 本地验证与下一步

已完成：原始请求一致性、截止位置和空检索字段检查；来源逐字投影；参考草稿严格协议通过、无规范化；7 段原文准确回填且没有重复选同段；3 条直接前提关联有效；三项金额用 Decimal 核对。代码 Ruff 通过，生成产物支持只读重建核对。

长度为 16,249 个来源字符、4,188 个草稿字符、8,294 个组装后 JSON 字符，都是 Unicode 字符而非 token。本例优先清楚展示出处和条件，保留了原任务等内容；不是已经优化到最短的 packet，不能据此声称获得实际 token 或费用收益。

从 GitHub clone 后，在 verl 根目录用 Python 3.10+ 复核已提交的来源、依赖、分片、输入消息、引用和 packet。这个入口只使用标准库和本仓库模块，不需要模型、API key、MemoryArena 安装或本地原始实验目录：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. python3 \
  examples/memory_agent_grpo/docs/training/shopping61_p2/verify_prepared.py
```

原始 `runs/` 文件未纳入 GitHub 交付；其哈希只作为来源记录保存。上述检查不声称重新验证了原始轨迹，也不认证语义。若本机保留原始实验目录，可进一步比较原始请求并重建全部产物：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=. ../MemoryArena/.venv-runtime/bin/python \
  examples/memory_agent_grpo/docs/training/shopping61_p2/build_sample.py --check
```

需要重新生成时使用 `--output-dir` 指向新目录，脚本拒绝覆盖已有目录。脚本只准备这个开发样本，不是通用数据集导出器，也没有改变 Shopping adapter 或任何默认 prompt。
